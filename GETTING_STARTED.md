# Getting Started: Creating and Working on a UiPath-Coders Project

This guide walks you through creating a new repository from the org template, setting it up in UiPath Studio, and making your first commit.

---

## Step 1 — Name your repository

Before creating anything, decide on a name following the org convention (see [NAMING_CONVENTION.md](./NAMING_CONVENTION.md)):

```
[vertical]-[use-case]-[type]
```

Examples: `hls-claims-automation`, `pharma-complaint-classifier`, `shared-doc-understanding`

Rules: lowercase + hyphens only, valid vertical prefix, under 40 characters.

---

## Step 2 — Create the repository from the template

1. Go to **https://github.com/UiPath-Coders/template-uipath-project**
2. Click **"Use this template"** → **"Create a new repository"**
3. Set the owner to **UiPath-Coders**
4. Enter your repository name from Step 1
5. Set visibility to **Private** (default for project repos)
6. Click **"Create repository"**

> Do NOT click "Initialize this repository with a README" — the template already provides one.

---

## Step 3 — Clone your repo

```bash
git clone https://github.com/UiPath-Coders/<your-repo-name>.git
cd <your-repo-name>
```

---

## Step 3.5 — Initialize the project in UiPath Studio *(UiPath Studio users only)*

> Skip this step if your project does not use UiPath Studio (e.g. Python scripts, standalone agents, or other non-Studio automation types).

> ⚠️ **Studio users: do not skip.** Studio's Git Init generates the correct `.gitignore` (excluding `.local/`, `.objects/`, `.autopilot/`, and other runtime folders) and scaffolds the project correctly. Manually initializing Git or creating project files outside of Studio will likely cause `.gitignore` gaps and `project.json` compatibility issues.

1. Open **UiPath Studio**
2. Go to **Start → Team → Open from Git** (or use **Clone Repository** if starting fresh)
3. Paste your repo URL and authenticate with your GitHub credentials
4. Let Studio open the cloned folder and scaffold the project — it will create `project.json`, `Main.xaml`, and generate the correct `.gitignore` automatically
5. Verify `.gitignore` is present in the root before proceeding

---

## Step 4 — Fill in the README

Open `README.md` and replace the placeholder sections:

- `[Project Name]` → your repo name in readable form
- One-sentence description
- Prerequisites (Studio version, Orchestrator URL, runtime dependencies, NuGet packages if applicable)
- Owner details (vertical, primary contact)

---

## Step 5 — Make your first commit

This is the one-time exception where you push directly to `main` — it establishes the base scaffold. All subsequent work should go through `develop` and feature branches (see Step 6).

```bash
git add .
git status   # verify no .env, credentials, or token files are staged
git commit -m "chore: initial project scaffold"
git push origin main
```

> If you completed Step 3.5, you can use Studio's built-in Team panel to stage and push instead of the CLI above — both are equivalent.

---

## Step 6 — Set up a working branch *(optional but recommended)*

Once `main` has the initial commit, setting up a `develop` branch keeps `main` stable and gives you a clean base for feature work.

```bash
git checkout -b develop
git push -u origin develop
```

For day-to-day work, branch off `develop`:

```bash
git checkout -b feature/your-name-short-description develop
```

If you choose to use this branching model, **never commit directly to `main` after the initial scaffold push.**

---

## Checklist before your first push

- [ ] Repo named following the convention
- [ ] README placeholders filled in
- [ ] `.gitignore` is present and confirmed — generated by Studio (Studio projects) or sourced from the template (non-Studio projects)
- [ ] `.local/`, `.objects/`, `.autopilot/` confirmed excluded *(Studio projects only)*
- [ ] No `.env`, `credentials.json`, Orchestrator tokens, or `appsettings.Production.json` staged
- [ ] Do not modify `.gitignore` without team review
